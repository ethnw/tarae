══ run
Run a shell command in the project, in the user's editor, and get how it ended and its output — build, lint, format, test suites, git. Not for reading or searching files: read and search do that in the editor, with no process and no card. The user watches it in their task panel. Both output streams come back whole (long output: its start and end), so don't redirect or pipe to head/tail for that. For git's reads the git tool is better (no card, no process). Any command runs at once in a sandbox: it reads the project, the repository's other checkouts, the temp folders, the Rust toolchain's sources ($(rustc --print sysroot)/lib/rustlib/src) or cargo's downloaded crates and outside home; writes the project (but its build files and .git: change those with edit), temp and the toolchain's own folders; reaches no network but this machine's open ports. Its report says what the sandbox blocked. To run somewhere other than the project root, give cwd rather than a cd. No stdin and no terminal: nothing interactive. For one test file or test, run_tests is better (it reads each failure). When the report says the command needs a place or port it blocked, run it again with also (that one thing) and your reason — the user decides on a card; a no holds for the chat, don't work around it. When it needs one unix socket outside the sandbox (a server's — colima's docker.sock), ask for that: unix_socket with your reason; when it can't work in it otherwise, you may ask to run it outside: outside_sandbox with your reason — the user decides on a card, this once.
══ run_tests
Run tests in the user's editor and get the results — after you change code, run the tests that cover it to check your work. Give a test file, and a line to run just the test (or test module/class) around it; without a line, the file's tests. The user watches the run in their editor. Call it once the edits it should check are made, not alongside them. Unsaved files are saved first. Rust (cargo test), Go, Python (pytest), Java (Gradle/Maven).
══ the chat's prompt
Both run in a sandbox: they can write only in the project (not .git, nor build scripts, manifests and tool settings — build.rs, Cargo.toml, .cargo, package.json, Makefile, .github, .tarae*.toml…: change those with edit), temp folders and the toolchain's own, and connect to nothing over the network, this machine included, but the ports the user opened (each result says which) — when it blocks something a command needs, run it again with also (that place or port, and your reason: the user decides on a card), else tell the user (the settings llm.sandbox-ports, llm.sandbox-localhost and llm.sandbox-network open more); never work around it.
