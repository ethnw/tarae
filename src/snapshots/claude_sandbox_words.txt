══ run
Run a shell command in the project, in the user's editor, and get how it ended and its output — build, lint, format, test suites, git. The user watches it in their task panel. Both output streams come back whole (long output: its start and end), so don't redirect or pipe to head/tail for that. Checks (cargo build/check/test/clippy/fmt/tree/metadata, go build/test/vet, git status/diff/log/show) start at once — words only (quotes are fine), alone or piped into grep head tail wc sort cut uniq, sed -n 'a,bp'. So do read-only ones (ls cat head tail wc grep rg find tree stat file du diff sort uniq cut pwd echo nm otool strings size, sed -n 'a,bp', git blame/rev-parse/ls-files/branch/show, git diff --no-index; git -C <dir> too) whose paths stay in the project, the repository's other checkouts, the temp folders, the Rust toolchain's sources ($(rustc --print sysroot)/lib/rustlib/src) or cargo's downloaded crates — and lines of checks and reads joined by ; && || |, with cd, for/while-read loops of reads, or the same in sh -c '…' (no other $, no backticks or redirects to files). To run somewhere other than the project root, give cwd rather than a cd. Any other command waits for the user to allow it — if they say no, don't retry it, ask. No stdin and no terminal: nothing interactive. For one test file or test, run_tests is better (it reads each failure). Commands run in a sandbox; when one needs one unix socket outside it (a server's — colima's docker.sock), ask for that: unix_socket with your reason; when it can't work in it otherwise (the network, writing where the sandbox doesn't let it), you may ask to run it outside: outside_sandbox with your reason — the user decides on a card, this once.
══ run_tests
Run tests in the user's editor and get the results — after you change code, run the tests that cover it to check your work. Give a test file, and a line to run just the test (or test module/class) around it; without a line, the file's tests. The user watches the run in their editor. Call it once the edits it should check are made, not alongside them. Unsaved files are saved first. Rust (cargo test), Go, Python (pytest), Java (Gradle/Maven).
══ the chat's prompt
Both run in a sandbox: they can write only in the project (not .git, nor build scripts, manifests and tool settings — build.rs, Cargo.toml, .cargo, package.json, Makefile, .github, .tarae*.toml…: change those with Edit), temp folders and the toolchain's own, and connect to nothing over the network, this machine included, but the ports the user opened (each result says which) — when it blocks something a command needs, tell the user (the settings llm.sandbox-ports, llm.sandbox-localhost and llm.sandbox-network open more); never work around it.
