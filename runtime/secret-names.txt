# for recovery; a plugin's `project` permission doesn't read or find them (asked like any file outside it);
# Claude's commands can't read one inside the project (the run's panel, space m s, opens that file).

# `!outside` lines: exceptions outside the project only — in a place a grant or a default opened to runs, and to
# Claude's reads there; in the project these names stay closed, as any key's.
# CA bundles: public certificates every TLS client reads — certifi's and curl's cacert.pem (a Python install's
# site-packages, conda's ssl/), the distributions' bundles: a `ca` name is a bundle by convention. Not `cert.pem`:
# it's a server's certificate and key in one file as often (Python's ssl docs make one so). By name only: a
# folder's (`ssl/*.pem`, `certs/*.pem`) would open the private keys kept there too. A toolchain's own files in a
# folder opened to runs read by where they are instead (the packs' `installs` and `packages`)
!outside cacert.pem
!outside ca-bundle.pem
!outside tls-ca-bundle.pem
